## 全部规则速览

### Harness 规则（P0-P1）

- **P0** Scripts 硬门禁：我说做完了不算，脚本判定通过才算
- **P0** Rule 是软约束但必须遵守：我说做了不算，脚本判通过了才算
- **P1** Rule 不能做到的，转为 Scripts：所有可判定的约束优先写成脚本
- **P1** Harness 优先于模型能力：问题先查 Harness 缺了什么，不先抱怨模型不够聪明

### Agent 规则（P0-P1）

- **P0** 不能越界修改：下游 Agent 不能改需求文档，只能提阻塞项
- **P0** 完成必须有验证：开发前后各跑一次基线验证脚本
- **P1** 单 Agent 冲突时拆角色：需求/设计/开发/审查/测试要分开
- **P1** 人的判断权高于 AI：关键决策必须由人来拍板

### Context 规则（P0-P2）

- **P0** 规则必须沉淀到仓库：不靠口头约定，不靠我脑子记住
- **P1** 先给目录再展开：AGENTS.md ≈ 100 行索引，不塞全文
- **P1** 规则必须写得可验证：AI 能写测试来判断规则是否满足
- **P2** 渐进式披露：先给摘要，需要时再给细节
- **P2** 优先用 Grep 搜索代码，不用预建索引

### 迭代规则（P0-P1）

- **P0** 不做多余假设：只处理需求明确说到的场景
- **P0** 最小化改动：新增字段 = 增加复杂度，非必要不加
- **P0** 尊重原有时序：能跑通就不重构，不改执行顺序
- **P1** 不确定就问：不假设业务上下文
- **P1** 合并收敛：相同逻辑合并到一处，不重复
- **P1** 不防御性过度：调用方可控的情况下不加多余判断

### 编码规则（P1-P3）

- **P0** 代码是负债：能删就删，死代码必须清除
- **P0** 不忽略任何错误：错误日志、异常、编译器警告都必须处理
- **P0** 不硬编码凭证：API key、密码、Token 必须用环境变量
- **P1** 简单接口 > 简单实现：封装复杂度，暴露简单接口
- **P1** 命名精确且一致：不缩写，名称长度和作用域成正比
- **P1** 注释写 Why 不写 What：顶部说模块目的，内部说修复方式
- **P1** 不提早优化：保留可扩展性，但不写现在不需要的实现
- **P1** 技术债零容忍 + 营地法则：提交比检出更好
- **P2** 追查根本原因：不贴创可贴，多问为什么
- **P2** 早部署常部署：完成部分就联调
- **P2** Code Review 是知识共享：不只是纠错
